## モーション設計案

以下は今回のオリジナル提案であり、観察サイトの実測値でも実装完了の証拠でもない。画像そのものは静止画。

| ページ | 動きの中心 | 提案する挙動と目的 |
| --- | --- | --- |
| 経営・運営統括 | 空間を貫く縦軸 | ヒーロー写真内をスクロールに応じ最大4%移動。建築の縦線とカタログの軸をつなぎ、支援領域の連続性を示す。本文は最初から読める |
| 同上 | カタログの選択 | hover/focusで180ms程度の罫線色変化、矢印は最大4px。項目の高さと位置は変えない |
| 収益・ブランド成長 | 写真が大きく開く | ギャラリー進入時に写真内のクリップを650ms、cubic-bezier(.22,1,.36,1)で開く。文字は隠さず、写真とサービスの焦点を合わせる |
| 同上 | 編集のリズム | 大写真と小写真の動きを40ms程度ずらす構想。矢印による任意送りを用意。自動で必須内容を流さない |
| DX・IT・調達基盤 | 分解模型から接続図へ | デスクトップのスクロールに合わせ模型の層を限定範囲で寄せ、オレンジの経路を順に強調。外観から導入・保守・調達の関係を理解する |
| 同上 | 保守と調達の接続 | 保守循環の現在の区間だけ色を変え、次章で線が素材写真の罫線へ着地。点滅や常時回転を使わない |

共通: 操作を待たせない。中断時は現在値から次状態へ切り替え、アニメーションをキューに溜めない。フォーカスを動かさない。モバイルは通常の縦スクロールと図の縦並びを基本にする。reduced-motionでは移動・クリップ・層の変形を止め、線と画像は完成状態で表示する。ブラウザ実装時のWCAG・レスポンシブ・性能検証は別工程。

### 原因と変更

初版を2つの独立したAstraレビューで確認。ひとつはHOMEとの構成・情報階層の差、もうひとつは原寸の文字・解像度・編集指示を検証した。ラスタにDOM検査は適用していない。

- 模型、接続線、ガラス、アメニティ写真が異なる表現体系になり、DXの説明より内装・商品陳列が目立った。廊下写真への置き換えも、一般的な写真＋テキストの反復を残していた。
- 初版は725×2169px。レビューの測定ではナビのインク高さ約8px、ヘッダーCTA約6pxに対し、FOUNDATIONは約152px。全体プレビューだけで細部の完成を判断したのが誤りだった。
- 初版の修正指示は、説明文を削りながら区画寸法を固定していた。空いた文章領域と長い矢印罫線が残った。
- オレンジの線が実装済み連携、保守の循環、単なる装飾を曖昧に混在させた。

v3は巨大なDX / ITと、3つの支援テーマへ直接進むオレンジの索引を入口にした。白のDXでは17・19を個別の行で示し、全面オレンジのITでは18と保守項目を整理。調達は濃紺に布・紙・金属のマクロ写真を重ね、20と4つの判断軸を提示する。モデル・廊下・化粧品の商品写真は使わない。HOMEとの共通項はADELVA、濃紺、オレンジ、白、細い罫線。DX / ITの幅広い文字は、この再制作で意図的に変更した。

途中生成で追加された英文・文章は除去。空白を残す固定編集を避け、DX / ITの大きさと調達写真の範囲を調整した。ヒーローCTAの「を」抜けは独立レビューの拡大確認で発見し、枠幅を広げて修正。最終保存先で「問い合わせを送信」、領域説明、4サービス、保守項目、調達属性、工程、問い合わせ・法務を目視確認した。全体と独立ヒーローは同じ方向の別レンダリングであり、ピクセル同一ではない。
