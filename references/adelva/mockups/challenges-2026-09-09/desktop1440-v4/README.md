## 原因の切り分け
1. 先行全ページ画像は724×2172px、1,572,528画素。1536×4608はプロンプトに記載した希望値であり、実現した出力サイズではなかった。生成後の寸法不足を受け入れたことが制作上の誤り。
2. 先行プロンプトは1:3の全ページに各章8〜10%を指定した。各章に使える高さは約174〜217pxしかなく、文字・写真・余白を詰め込む構成を自ら指示していた。
3. 最初の修正も1024×1536px、1,572,864画素であり、1440pxのデスクトップ設計ではなかった。分割だけで十分と判断し、必要な横幅を確認していなかった。
4. 保存ファイルはPNG。最初の修正のツール返却data URLと保存原本のbase64長はともに2,895,528、FNV-1aはともに2304498759。返却表示データと保存ファイルの不一致を示す証拠はない。保存時のJPEG劣化とは違う。
5. 観測した出力が約157万画素に揃っていることは確認したが、内部の画素上限、生成モデル、品質設定、リサイズ実装は非公開。内部原因を確定したとは扱わない。現行built-in imagegenの引数にはsize/quality/modelはなく、プロンプトだけで正確な出力寸法を保証できない。
6. チャット上のプレビューの表示倍率は当方から確認できない。プレビュー縮小と原本の品質を混同しない。1440pxでの確認には最終PNGを100%表示する。

- 全原本が1440px幅以上。低解像度画像の拡大、非等方の引き伸ばし、切り取りなし。
- 連結時に幅のみ1440を指定して縦横比を維持。最大約8.7%の比例縮小がある。「一切リサイズなし」「元画素をそのまま連結」とは主張しない。途中の左右1px切り取り案は不採用。
- 最終PNGは可逆圧縮。ファイルサイズ圧縮と空間解像度の縮小は別。正規化後の全5区間のRGB画素ハッシュが、最終PNG内の対応領域と一致することを検証。連結による追加リサイズ・画素変化なし。
- 最終総画素数7,329,600。先行全ページ画像の約4.66倍。単なるアップスケールによる増加ではない。
- 原寸画像を目視し、ヘッダー、日本語ヒーロー、5索引、同格の2対象者、01〜05見出しと説明、10支援テーマ、6工程、問い合わせCTA、footerを確認。文字・写真の非等方変形や切断なし。
- ピクセル内のフォントサイズはモデルによる近似であり、プロンプト指定の16〜20pxを実測したとは扱わない。ブラウザのCSS実装・アクセシビリティ・レスポンシブの合格ではない。
