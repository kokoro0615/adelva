# White Desert interaction/state audit

Date: 2026-08-30 JST

Target: `https://white-desert.com/`

Scope: public home, enquiry, and the long-form region route `https://white-desert.com/antarctica/fuel-depot`.

## Method and evidence boundary

- Playwright 1.62.1 with the installed Google Chrome executable (`/usr/bin/google-chrome`), DPR 1, light color scheme.
- Every navigation used `waitUntil: "domcontentloaded"` followed by a bounded 0.7–1.5 s wait. The target's persistent video was never allowed to make the run wait on `networkidle`.
- Captures use the exact CSS viewports `1440x900`, `768x1024` where the responsive behavior changes, and `390x844`.
- Menu clicks, keyboard input, hover, scrolling, and disabled-control inspection were read-only. No enquiry was submitted. The enquiry page emitted automatic analytics POSTs during page load; no form POST/GET was initiated by the audit.
- Target screenshots and target assets are research-only. Some fresh-context captures include the target cookie notice; no Accept/Reject action was taken.

## Enquiry form (`/enquire`)

The empty form was inspected and captured at both required viewports. The first form is `action="https://white-desert.com/enquire" method="get"` with `noValidate=false`; all season, month, and interest toggles are unselected, and the visible `button.submit-button` is `type="submit"`, text `Submit Form`, and `disabled=true` (`693x140` at desktop, `326x140` on mobile). There are no native `required` attributes and no visible error/status text in the empty state. The form is a single progressive layout with no `Next` control. Because the only submit control is disabled and the form action is the target URL, the audit did not activate it and did not attempt any validation/progression that could submit or navigate.

### Blocker

No meaningful reduced-motion fallback was observed on either audited route: Lenis remains initialized, home hero blur/cloud transforms remain scroll-driven, and the long-form reveal animation plus banner transforms remain active under `prefers-reduced-motion: reduce`. The implementation should treat this as an explicit accessibility requirement rather than copying the target behavior unchanged.
