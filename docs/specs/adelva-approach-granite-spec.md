# ADELVA 支援の進め方：巨岩と森の大庭園

## 採用と範囲

2026-09-10、ユーザーはA1「巨岩と森の大庭園」を採用し、調査・計画後のデスクトップ／モバイル実装を指示した。image-to-code Mode B。対象はHOME `/` の `TravelRoute`、直前のCPT–WFR・白い霧の接続を含む。新しい `#approach` は同じHOME内の到達点。新規下層ページ、グローバルメニュー、他のセクションや動画モーダル、フォーム、公開設定は変更対象に含めない。

採用画像：`references/adelva/mockups/approach-2026-09-10/monumental/A1-granite-garden.png`。
A2・A3への方向変更はしない。建築が小さく見える岩壁のスケール、森の奥行き、道を辿る体験が視覚上の優先事項。

## 調査と判断

### 巨大さは画面に全部収めることで失われる

旧実装は幅に比例して地図・線を縮小し、390pxでは曲線が約160px高となった。6工程を追加すると文字の過密化とスケール喪失を同時に起こす。採用A1は縦長の全景であり、デスクトップも一画面ですべてを表示する設計にはしない。1440px幅では写真を1920px高で表示し、巨大な岩壁と複数の工程をスクロールで辿る。

White Desert公式HOMEは実際の地理、2地点、線、飛行情報を一つの意味にしている。前回調査の3指定画面サイズで、既存実装の線が約0→50→100→50%と逆方向にも追従することを確認済み。本改修は連続性と逆スクロールを維持し、地理を改善工程へ置換する。[1]

### モバイルは別の撮影構図でスケールを保つ

新しいモバイル素材は724×2172px、デスクトップ素材は1086×1448px。モバイルは同じ世界を縦に再構成しており、単なる中央切り抜きではない。岩壁、入口、行き先がすべてフレーム内に入る。390px幅で1170px高の自然比率とし、画面高さに合わせた `cover` 切り抜きはしない。

`picture` によるアートディレクションは一つの表示画像に画面条件別ソースを用意できる。Next.jsのインストール済みガイド `node_modules/next/dist/docs/01-app/03-api-reference/02-components/image.md` のArt direction例を確認した。2つの画像をCSSだけで隠し分けて両方読み込ませず、ブラウザが適切な画像を選ぶ構造とする。[2]

### 動きの役割は支援のつながりの説明

背景と線の座標面を同じにする。写真単体をパララックスすると、線が石の道を外れる。今回は画面の自然なスクロールによる移動と、一つの経路の描画に絞る。ピン留め、追加のスクロール拘束、常時波紋、背景の大きなズームは設けない。

GSAP ScrollTriggerは事前計算した始終点でスクロール進行を扱い、refreshで配置を再計算できる。既存Lenis連携を保ち、同じGSAPインスタンスと `useGSAP` のスコープ・破棄を使う。読み位置に合わせた経路先端は、SVG経路上のY位置と画面内の読書基準位置から求め、戻り・大きなジャンプでも追従する。毎フレームReactを再描画しない。[3]

WCAG 2.3.3はAAAでありAA必須と混同しないが、このリポジトリではreduced-motionが必須。reduceおよびJavaScriptなしでは全工程・全線が初めから見える。JSの動作成功を読むための条件にしない。[4]

### 説明は事業原稿を使う

工程は「課題把握／判断／実行・実装／運用／検証／引継ぎ」。景観上は各工程名のみとし、長文で写真を覆わない。写真の後の短い本文領域に承認済みコピーを掲載する。

「課題把握から、判断、実行・実装、運用、検証、引継ぎまで。」

「分析や助言で終わらず、責任分界とKPIを明確にし、支援終了後もお客様自身が継続して改善できる状態をつくります。」

出典は `references/adelva/sources/home-copy.md` §5。架空の成果、支援期間、施設名、社員・顧客を追加しない。画像は概念風景であり事例写真ではない。

## DOM・レスポンシブ・状態

- section `id=approach`、`aria-labelledby=approach-heading`、既存検証ID `data-fidelity-section=travel-globe` を保持。旧意味のclassは使用しない。
- scene内：picture、視覚用SVG（aria-hidden）、header h2、日本語副見出し、1つのolに6つのli。順序付きリストは読上げから消さない。
- 各工程は同じDOMをdesktop/mobile座標で配置。重複した読上げ用リストを作らない。
- SVGにはdesktop/mobileの経路群を持ち、media queryと同じ条件で一方だけ表示。進捗は表示中のpathに対して計算。
- mobileは幅600px未満。600〜1023pxはdesktopの自然比率で文字だけ調整。200%ズーム時も順序・コピーを保持し、レイアウトを横にあふれさせない。
- JS前は全線表示、全工程可読。通常motionでのみスクロール進捗を有効化。reduceへ切り替えると描画進捗・インラインstyleを解除し、全線へ戻す。
- ScrollTriggerは自身のsectionスコープのみ。フォント準備とリサイズで更新し、matchMedia/useGSAPのcleanupで破棄。setStateをスクロール更新に使わない。
- animation目的はExplanation。スクロール量から直接求める線形進捗。待ち時間・自動再生・クリック・hoverを必要としない。
- 既存fixed utilityが写真右端にあるため、ラベルは右端から少なくとも76px離す。本文位置で隠す必要が生じても共有挙動は勝手に変えない。

## Deterministic capture / acceptance thresholds

専用ビルド出力とポート4191を使用し、現タスクのDOM `data-approach-scene` が配信されていることを確認。3指定画面サイズでheader/start、01、03、06、後続説明、reverse、reduceを観測。主要参照はscene全景を自然比率でキャプチャし、承認A1を同じ比率で正規化して比較する。tabletはこの仕様に対する検証であり承認済みmobile/desktopを引き延ばした参照にしない。

| ゲート               | 事前の合格条件                                                                                                                                                        |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 全景／画像           | scene比率±1px、ソース選択正しい、画像decode成功、文字焼込みなし、入口と宿泊棟が残る                                                                                   |
| 原画との構図         | 自然px換算の歩道・建物位置±12px。desktop対A1の全画面画素差は、文字除去と明度変更を含むため診断値として扱う                                                            |
| 写真派生素材との比較 | 上下フェード・文字・経路を除く左岩面の自然比率範囲x0.02〜0.18,y0.32〜0.60を両画像同じ方法で取得、明度処理を含む正規化MAE≤0.16。位置・比率違いは画素指標だけで通さない |
| 経路進行             | start≈0、mid中間、end≈1、reverseで同じ位置の値差≤0.005。nodeは経路から12自然px以内。no-motionでは全線                                                                 |
| 日本語               | 6工程が1回ずつ、ラベルが隣のラベルと重ならず横溢れなし。モバイル文字16px以上                                                                                          |
| a11y                 | scoped axe WCAG2.2AA 0違反、工程を読み上げられる、200%ズーム、動きなしでも情報欠落なし                                                                                |
| 回帰                 | CampsFlow→approach→planning順、7直接子、共有ヘッダーのキーボード・Escape、scroll-lockに影響なし                                                                       |
| 技術                 | 実format/lint/typecheck/unit/Playwright/axe/visual/reference/buildの結果を記録。既存の別範囲失敗は成功と報告しない                                                    |

## 実ブラウザ調整・追加指示

- 原寸の道を再採寸し、`docs/reports/adelva-approach-implementation-2026-09-10/path-survey.json` に中心線の測点を保存。上の初期節点表を置換する最終節点は `src/content/adelva-approach.ts`。各節点は測点を通る曲線上に置く。
- ユーザーの「移動する光が見えにくい、線も・もう少し光ってほしい」に合わせて、通過線を2.2CSSpxの金色へ、進行点の白い中心を半径6.5CSSpxへ変更。外周26pxの柔らかな放射グラデーションと、150/90/35CSSpxの3段階の短い光の尾を加える。尾は経路上の進行点の後ろだけに描き、常時点滅はしない。画面サイズによらず同じCSS寸法を維持。reduce・JSなしでは尾／進行点を隠し、連続線を全表示。
- reduced-motion切替時、前段CampsFlowが横移動／縦積みに変わりsceneの文書位置が大きく変わる。テストでは再度同じ読書位置へスクロールし、再初期化と進捗を検証する。
