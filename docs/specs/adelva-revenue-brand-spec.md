## 6. 実測した寸法（Measured geometry）

### 6.1 デスクトップ（1024 px 以上。単位 u＝幅 1440 のページでの CSS px）

ステージ幅 `W = min(100cqw, 1920px)`、`--u = W / 1440`。1920 を超える幅はステージを中央に置き、左右は `--ink-page`。写真・線・節点・チップ・文字ブロックは、すべてステージ内に u で絶対配置する（経営・運営統括の `--u` と同じ考え方）。プレート px → u は ×0.9375。

## 9. モーション

前提（AGENTS.md）：ふつうの状態変化は CSS。計測を伴うスクロール演出だけ GSAP/ScrollTrigger（`useGSAP`、スコープ付き ref、クリーンアップ）。時間とイージングは `src/lib/motion.ts` の `DURATION`・`EASE_*` と `globals.css` の `--dur-*`・`--ease-*`。自動で動き続ける要素は置かない（WCAG 2.2.2）。文字と操作部分は最初から表示し、演出の完了を待たせない。`filter: blur` をアニメーションしない。`gsap.matchMedia()` で `(prefers-reduced-motion: no-preference)` の時だけ演出を登録し、reduce では登録しない（完成状態のまま）。

初期化の順序：サーバーの HTML は完成状態。JS が有効で reduce でないときだけ、CSS の `@media (scripting: enabled) and (prefers-reduced-motion: no-preference)` がヒーローの源流・チップ・節点を最初の描画から未描画にし、モーションの部品が描く（`.page[data-motion="on"]` になるまで。3 秒のフェイルセーフで完成状態）。インラインの `<script>` は使わない（React 19 はクライアント描画で実行しないため。2026-09-29 修正）。

### 9.2 スクロールに連動する川の線（ページの背骨）

- **経路**：`paths.main`（SCROLL の下端 → 終点の四角）。その下に、同じ経路の `track`（白 1px、不透明度 .28、湖の区間は点線 `2 6`）を常時表示する。
- **描画量**：スクロール位置から「ビューポートの上から 58% の高さ」に当たるページ y を求め、main 上でその y に最初に到達する長さ L を求める（経路を 4 plate px ごとにサンプルした「長さ→y の単調最大」表を作り、二分探索）。描画量は `gsap.quickTo(proxy, "len", { duration: 0.6, ease: "power3.out" })` で滑らかに追従（ScrollTrigger の `scrub: 0.6` 相当）。
- **橙の線は 3 重**（ぼかしフィルタを使わずに光を作る。巨大な SVG へのフィルタは重い）：外側 11u `rgb(255 126 21 / 12%)`、中 5u `rgb(255 126 21 / 45%)`、芯 2u `#ffb070`。すべて `stroke-linecap: round`、同じ `stroke-dasharray`/`offset`。
- **湖の区間**（`lakeDottedRangeY`）：橙も点線（`dasharray` を別に持つ複製を、y 範囲の矩形マスクで出し分ける）。
- **文字の下**：`lineMasks` の矩形では線を消す（マスクの黒い矩形。上下 24u は線形グラデーションで柔らかく消す）。文字ブロックの位置を変えたら矩形も合わせる。
- **頭の光**：半径 7u の放射グラデーションの円（中心 `#fff3e6`、縁 透明）＋芯 2.5u。`getPointAtLength(L)`。L が 0 と終点ではフェード。
- **性能**：更新は scroll 時だけ。`getPointAtLength` は表から引く（毎フレームの DOM 計測をしない）。描画量の表はリサイズ時と `ScrollTrigger.refresh` 時だけ作り直す。
