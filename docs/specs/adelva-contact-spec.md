作成: 2026-09-29（Opus 5.5）。実装前に書き、計測値はモック自身の HTML 組版から取得した（`scripts/adelva/measure-contact-mock.mjs desktop|mobile`）。

## 1. 採用と範囲

- 採用案: `references/adelva/mockups/contact-r2-2026-09-29/C2/C2-full.png`（1440）と `C2/mobile/C2-mobile-full-390.png`（390）。ユーザーがC案を選び、C2 と C2 モバイルを経て「忠実に実装」を依頼（2026-09-29）。既存の `/contact`（白地の準備中フォーム）は置き換える。
- ワークフロー: image-to-code Mode C（精密な採用デザインあり）。画像の新規生成は行わない。写真はモック制作時のクリーンプレートと「霧の晴れた版」をそのまま配信用に変換する。
- 実装者: Opus 5.5（ユーザー指定）。

## 5. 本番の文字列

承認済み（出典は `contact-2026-09-29/README.md` §4、IA §11）: H1「課題が整理できていなくても、お問い合わせいただけます。」（H1としての使用は要承認）、5つの課題、「01 経営・運営統括」「02 収益・ブランド成長」「03 DX・IT・調達基盤」、「課題把握」「支援の進め方を見る」「問い合わせを送信」「お問い合わせを受け付けました」「プライバシーポリシー」、ナビ一式。

要承認（モック第1〜2回で提示済み）: 「お問い合わせ」「CONTACT」、「近いものを選んでください。いくつでも選べます。」「まだ整理できていない」「関連する支援領域」、「ご立場を教えてください。」「オーナー・経営者」「総支配人・現場責任者」「その他」、「ご相談したいことを、自由にお書きください。」「箇条書きや、思いつく順でもかまいません。」、「ご連絡先を教えてください。」「会社名・施設名」「任意」「お名前」「メールアドレス」「電話番号」「メールアドレスを入力してください。」、「ご相談の概要」「プライバシーポリシーに同意する」、レール「課題」「ご立場」「ご相談内容」「ご連絡先」、「送信後の流れ」「問い合わせを送信」「内容の確認」「担当者からのご連絡」「課題把握」、「このフォームについて」「新しいご相談の受付窓口です。」「緊急の障害対応やサポートの窓口ではありません。」「個人情報の取り扱い」「入力いただいた内容は、お問い合わせへの回答に使用します。」、「送信中…」。

既存サイトから引き継ぐ: 「入力内容を確認してください。」「メールアドレスの形式を確認してください。」「現在フォームは準備中です。入力内容は送信されません。」（送信先が未設定のときだけ表示）。

実装で追加（要承認・同じ型の短文）: 「近いものを選んでください。」「ご立場を選んでください。」「ご相談内容を入力してください。」「お名前を入力してください。」「電話番号を入力してください。」「電話番号の形式を確認してください。」「プライバシーポリシーに同意してください。」「送信できませんでした。入力内容はそのまま残っています。時間をおいて、もう一度お試しください。」、スクリーンリーダー専用「（新しいタブで開きます）」。

課題→支援領域の対応は既存の `challengeBands`（`src/content/adelva-challenges.ts`）の `[0,0,0,1,2]` を使う。「まだ整理できていない」は領域なし。

### 8.4 送信先

`src/lib/contact-delivery.ts`（サーバー専用）。`CONTACT_WEBHOOK_URL` があれば JSON を POST（8秒でタイムアウト）。`CONTACT_DELIVERY=accept` は本番以外でだけ有効な受理のみのモード（e2e・プレビュー用、内容は記録しない）。どちらもなければ「未設定」。同じ `submissionId` は10分間1回だけ受け付ける（インスタンス内）。

## 11. アクセシビリティ

- 見出し: h1 → h2（各質問、送信後の流れ、注記2つ）。番号は `aria-hidden`。
- カードは実物の `input`（全面を覆う透明な入力）で、Tab・Space・矢印（radio）が効く。フォーカスは2pxの生成りの輪。
- エラーは文字と「!」で示し、色だけに頼らない。一覧は `role="alert"`、各欄は `aria-describedby`。
- 関連する支援領域・概要は `aria-live="polite"`。送信中は `aria-busy`。
- 文字の背後は霧の影（`--pool`）と文字影でAAを確保し、実測（写真上の輝度90パーセンタイル）で確認する。
- 自動で動き続ける要素はない（2.2.2）。reduce では演出をすべて即時にする。

## 12. 性能

- 写真は AVIF/WebP の `srcset`、最初のタイルだけ preload（`fetchPriority: high`、media 付き）。全タイルに寸法を与え CLS 0。
- 晴れた版は操作の後に読み込み、マスクは JS で GSAP tween（1枚の要素のマスク文字列を書き換え、rAF で1回）。
- WebGL なし、Lenis なし（フォームの自然なスクロールとフォーカス移動を優先）。
- 動きのための層は motion 許可時だけ `display` する。
