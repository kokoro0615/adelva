## 決定事項

- 先端・尾・灯りは写真と同じスクロール層（ステージ内）にあり、ネイティブのスクロールで写真と一緒に動く。JS が決めるのは川に沿った進み具合だけで、減衰して追従する。固定と非固定の切り替えも、ビューポートに貼り付けた要素の移動もないので、R1 の「泳ぐ」問題は起きない（R1 の (a)–(c) のどれにも当てはまらないが、趣旨に沿うと判断）。
- 映り込みの新しい波紋はデスクトップにも適用した（Safari デスクトップも SVG フィルタは CPU）。見た目は細い帯の横揺れで、強さ・止まり方は従来と同じ考え方。
- 映り込みのフェードの向きを A4 どおりに直した（見出し側が濃い）。
- 湖の上の先端を 40% に落とした。プレートの描き直しで「湖の光る玉」を消す方針と合わせるため。
- 1023 以下の灯り・夜明け・窓は、合成モードをやめて色と透明度の定数で近づけた。完成状態の旅館まわりを変更前と並べると（`sheets/dawn-390-before-after.webp`、左が変更前）、変更後はわずかに明るく霞む（soft-light の締まりがない）。差は小さいので、新しい写真の上で合わせ直す（下記）。
- 霧は全幅でアルファ付き画像に置き換え（screen と数学的に等価、色は霧の平均色で一定）。旧 `f1/f2-*.webp` は削除した。
- 599 以下で固定レールを出さない。電話では川そのものと工程のカウンターが進み具合を示す。
- 389 以下は構図ごと縮める（12px の下限は維持）。390 以上の見た目は変えていない（SNS の源流チップの 1px を除く）。
- サービスの違いの各行の登場位置を 70% → 88% に（行の節点と桟橋の線が先に描かれていて、文字だけ遅れると「欠けて」見えた）。
- このページから MotionPathPlugin を外した（粒は自前の長さ表で動かす）。

## 残課題

- 実機（iPhone Safari）での確認はしていない。測定はヘッドレス Chromium（SwiftShader）と WebKit。
- 新しいプレートの統合と、その上でのコントラスト・色の再確認。
- 一度だけ観測した小さな CLS（文字ノード、合計 0.0011）。2 回の再現試行では出ず。
- 章1 の支流・引き出し線・SNS の循環の残り半分は、1 回だけ線を描く（stroke-dashoffset、最長 1.6 秒）ので、その間は自分の SVG 層を描き直す（マスクのない小さな経路。ブリーフの許容範囲）。
