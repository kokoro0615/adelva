## 6. 画像の貼り付け防止（§0.5）

1. **全文字列が DOM テキスト**：e2e で `requiredStrings`（§4 の全文字列）を 3 ビューポートと JS なしで確認。写真の `alt` はすべて空。
2. **画像を消した撮影**：`noimg-{desktop,tablet,mobile}-full.webp`。文字、UI、引き出し線と点、括弧、4 目盛り、乗り場の線、チェック、状態表示がすべて残る。
3. **配信画像の検査**：§3 のとおり 20 枚すべてを原寸で確認。
4. **固定区間は層と DOM で変化**：`process-states.json`。進行 0 / 0.6 / 1.0 で `data-progress` 1→4→6、工程の `data-state`（current に `aria-current="step"`）、かごの `translateY`、扉の `clip-path` `inset(0 50%)`→`inset(0 0%)`、夜明けの不透明度 0→0.85 が変わり、表示中の画像は 3 枚（base・lit・cabin）で不変。

## 7. 支援の進め方で採った方式と理由

- **層**：L0（暗）／L1（点灯）／L2（かご、`mix-blend-mode: screen`）／L3（SVG の線）／L4（HTML）。L1 は縦坑の柱の範囲だけをかごの位置まで上から見せ、扉は中央から開く `clip-path`、下 1/3 の暖色は不透明度で出す。
- **毎フレームの書き込み**：最初は `.plate` の CSS 変数を更新していたが、配下約 108 要素のスタイル再計算が毎フレーム発生した（CPU 4 倍低速で長いタスク 134 件）。動く 5 層の `transform`／`opacity`／`clip-path` を直接書く方式に替え、長いタスク 3 件、フレーム中央値 16.8ms に改善。CSS 変数は「JS なし／reduce の完成状態」の既定値としてだけ残した。
- **吸着の方式（指示書の想定どおり変更）**：ScrollTrigger の `snap` は Lenis 併用時にホイール後に発火しなかった（実測：0.29 の位置で停止）。スクロール終了時に次の乗り場へ寄せる処理を唯一の担い手にした（遅延 0.08s、0.25〜0.6s、`power3.out`）。寄せる先は最寄りではなく**進行方向の次の乗り場**。最寄り方式では矢印キーや軽いホイールで先へ進めず、キーボード利用者が進めなかったため。入力があれば寄せる動きは即中止する。
- **共通ヘッダーとの両立**：キーフレームにはヘッダーがない。舞台はヘッダー分を空けて配置したが、ヘッダーの「読みやすさ用の暗幕」がバー下 76px までぼかされ、01 の段が暗くなった（明るさ 185/255）。固定区間の間だけ `--nav-veil-feather` を 0 にし（バー内の文字の保護は維持）、01 の段はモックと同じ明るさ（255）になった。
- **06 のコントラスト**：夜明けの光が最大（0.85 で制限）の状態で、06 の工程名 15.65:1、タグ 16.94:1（4 ビューポートで実測、`contrast.json`）。
