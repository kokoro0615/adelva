# HOME HERO動画 v3 への差し替え

対象は `/` の背景動画と、読み込み時に表示する静止画。ユーザーの指示（2026-09-30。素材の使用許可は取得済みとの申告あり）により、
`~/projects/_tools/video/output/aman-film-v3-lab/renders/final/` の4本に差し替えた。
制作過程と数値の記録は、同フォルダの `README.md` にある。

## 原因（実測）

- 10カット中9カットの元素材が、768×432のiStockプレビュー版である。
- 以前のAI拡大（RRDB＋SeedVR2 3B）で、ブロブ状・蝋状の質感が出ていた。
- スマホでは、横長の動画の中央26%だけを約4.4倍に拡大して表示していた。
- エンコードが何度も重なっていた。
- 配信のビットレートとCSSは、主因ではない。

## 映像の処理

1. `enhanced-4k/` のカット別素材を768×432に縮小した。
2. SeedVR2 7B sharp（Q4 GGUF、バッチ9、36フレームずつのストリーミング処理）で1080pに拡大した。
3. 双方向・動き追従の時間安定化と、処理の区切り目（チャンク境界）の平滑化を行った。
4. v2と同じ編集と色補正を再現したうえで、カットごとに現行へ色を合わせ、控えめな仕上げを加えて、1回だけエンコードした。
5. ネイティブ4Kの霧の森は、SRにかけていない。
6. 尾根カット2本は1回の連続処理で拡大し、ループのつなぎ目を同じ時間文脈の中に置いた。

## 修正（2026-10-01）：AV1版を配信しない

ユーザー報告：「ローカルでは普通だが、Vercel本番のPC表示が崩れている」。

- 本番の動画4本は、ローカルとバイト単位で同一（MD5一致）。範囲指定の取得（206）も正常で、配信経路の問題ではない。
- ローカルで確認していた比較ページ（lab の `review/compare.html`）と、本番ページ上でのレビューは、どちらも **H.264版** を再生していた。本番のPCブラウザは、`<source>` の先頭にある **AV1版（CRF28）** を選ぶ。AV1版は、目視レビューを一度も通していなかった。
- AV1版をH.264版と比べた実測値：
  - 細部の量（高周波エネルギー）：平均 −10%。草・岩肌が平らになる。
  - キーフレーム（48フレーム＝2秒ごと）の前後で、質感が跳ぶ。15か所中13か所で、周囲の1.4〜2.2倍の変化があった。H.264版で同じ位置に跳びが出たのは、1か所（1.37倍）だけだった。
  - Chromium（ソフトウェア復号）では、AV1の10bit・1080pの再生で落ちるフレームが多かった。ただし、ユーザーのPCで同じことが起きているかは確認していない。
- 対応：AV1の候補を `<source>` から外し、レビュー済みのH.264 CRF18版だけを配信する（ユーザー承認済み）。
  - PC：横長H.264（47.5MB。v2の46MBとほぼ同じ）
  - スマホ・タブレット縦：縦長H.264（40.4MB。AV1版の15.3MBから増える）
- AV1の2本（`hero-antarctica-av1.mp4`・`hero-antarctica-portrait-av1.mp4`）は、どこからも参照されなくなった。ファイルは `public/` に残してある。
- 同じデプロイで、White Desertから引き継いだ「How it works」タブ（右端のオレンジのタブと、開くパネル）を撤去した（ユーザー承認済み）。パネルには、元にした事業者の英文と営業担当の予約リンクが残っていた。
